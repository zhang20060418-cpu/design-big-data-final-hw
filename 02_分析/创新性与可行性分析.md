# 创新性与可行性分析

> 核查日期：2026-10-22
> 结论口径：以本科课程期末项目为标准。不套用顶会标准，也不放宽到"能跑就行"。

---

## 0. 结论先行

**创新性：够用，但必须重构表述。** 三个创新点逐个拆开看，每一个都有明确先例；组合起来、限定在"AI 生成 PPT 的交付前审查 + 成本量化"这个场景里，确实有空位。现在的写法（"构建分层检测框架""建立结构化证据体系"）属于描述做法，不是陈述贡献，容易被问成"这不就是……吗"。必须改成"别人做到了哪、我多做了什么、用什么指标证明"。

**可行性：核心可做，全套做不完。** 按 9 项最低交付全做，估算约 110 工时，两周实际可投入约 60–80 工时，缺口 30%–50%。砍掉三项后（AI 味标注、PresentBench 全量、五方案对比），约 75 工时，可完成。

**一个必须先解决的前提：** 两周的真正瓶颈不是算法，是**渲染管线**。它如果第 3 天还没跑通，后面全部要返工。

## 1. 文献核查结果

### 1.1 SlideAudit 真实存在，且情况比描述更有利也更棘手

| 项目 | 核查结果 |
|---|---|
| 出处 | UIST 2025，arXiv 2508.03630，DOI 10.1145/3746059.3747736 |
| 规模 | 2400 张 = **600 原始 + 1800 合成**（同一原图的 3 个改动版） |
| 来源 | 公开 Google Slides、既有语料、**AI 系统生成（含 Gemini）** |
| 标注 | 17 位设计专家做形成性研究定 taxonomy，Prolific 众包标注，含 `has_strong_agreement` 字段记录分歧 |
| 字段 | `annotations`（类别 + 缺陷名 + 是否命中 + bbox）、`descriptions`（元素类型 + 归一化 bbox + 文本） |
| 许可 | CC BY 4.0，可自由使用 |
| 附带 | 评估脚本尚未发布（仓库 TODO 中） |

**论文结论对项目极其关键：** 作者用多个 LLM 在多种 prompting 策略下识别设计缺陷，**F1 仅 0.331–0.655**，并明确指出"AI 难以准确识别幻灯片设计缺陷"。taxonomy 引导的 prompting 效果最好。

这句话同时是**最强的立项理由**和**最大的撞车风险**：

- 立项理由：领域内已用实验证明"单纯让大模型看图审 PPT 不够用"。项目要做的分层协同，正是对这个负结果的回应。
- 撞车风险：论文本身就是"自动化幻灯片评估"。项目的"通用质量缺陷检测"部分，如果不做出差异，就是在这篇论文的下游做复现。

**两处必须注意的技术事实：**

1. **全是图像，没有可编辑 PPTX。** `descriptions` 里的元素 bbox 是从图像检测出来的"伪结构"，不是原生 XML 坐标。所以项目的"结构证据"优势在 SlideAudit 上**体现不出来**——它只能用于验证视觉层，验证不了规则层。
2. **数据泄漏风险比预想更严重。** 600 原始 → 1800 合成，每张原图有 3 个改动版。若按图片随机划分训练/测试，同一张原图的不同版本会跨集，模型可能学到"改图痕迹"而不是缺陷特征。必须**按原始页面分组划分**。这条修起来很便宜，不修则实验一全部指标作废。

### 1.2 PresentBench 真实存在，但性质与描述有偏差

| 项目 | 核查结果 |
|---|---|
| 出处 | arXiv 2603.07244（2026-03），presentbench.github.io |
| 规模 | 238 个评测实例，每例**平均 54.1 条 checklist** |
| 内容 | 背景材料（PDF/MD）+ 生成指令 + 评分清单。**不含任何 pptx** |
| 许可 | 原创部分 CC-BY-NC-4.0，背景材料沿用原许可 |
| 榜单 | NotebookLM 62.5 居首，Gamma 49.2，PPTAgent v2 50.2 |

**它的真实价值不是"训练数据"，而是两件更具体的事：**

1. **checklist 天然就是"可核验条件"的范本。** 每条是二值问题，正好对应项目里 `Condition` 结构的设计。可以拿 20–30 条真实 checklist 来检验"自然语言要求 → 结构化条件"的拆解质量。这比空想拆解规则靠谱得多。
2. **它是一份现成的"AI 生成任务集"。** 238 个真实生成任务，可挑 10 个驱动自建样本，省掉自己编 prompt 的工作。

但它**不能**当训练集，也**不提供** PPTX。原交接说明里"不应直接视为完整训练集"的判断是对的，需要更精确：它不是训练集，是**条件拆解的参照集 + 任务来源**。

### 1.3 已有工作比预想拥挤，且都在这条路上

| 方向 | 代表工作 | 做到了什么 | 对本项目的含义 |
|---|---|---|---|
| PPT 缺陷数据集 | SlideAudit (UIST'25) | taxonomy + 2400 标注 + LLM 基线 F1 0.33–0.65 | 通用缺陷检测已是"红海"，必须差异化 |
| PPT 生成质量评测 | PPTEval (EMNLP'25)、PresentBench | 内容/设计/连贯性三维打分；细粒度 rubric | 都是"打分"，不定位缺陷、不举证——正是本项目要区别的对象 |
| 规则 + LLM 混合审查 | *AI Is Not Enough*（CHI EA'24，UI linting） | 用启发式从 view hierarchy 提属性，配设计文档 RAG，交 LLM 判合规 | **最接近的先例**。但它只有两层（启发式 + LLM），没有 ML 层，也没做成本量化 |
| 设计缺陷 CV 检测 | UIS-Hunter、Nighthawk | 深度学习检测像素级 design smell | 说明"视觉缺陷分类"技术成熟，ML 层不构成创新 |
| 设计批评系统 | CritiqueCrew、UICrit、UIGuider | 多视角批评、知识图谱评估、大规模反馈数据 | 领域共识：现有工具是 "problem auditor" 而非 "critique partner" |
| AI 生成内容检测 | Turnitin AI Indicator、PPTDetector 等商业产品 | 直接判"是否 AI 生成"，给概率分数 | **本项目主动避开这条**，改判可观测现象——这是对的 |

### 1.4 两个可以直接引用的论点

**论点一（技术依据）：** 2026 年对多模态推理的评测工作得出一个明确判断——"视觉应当进入系统，但**经过验证的结构**应当承担推理负担"，并指出"让模型对图像做视觉思维链"属于朴素做法，更稳健的是"提取为结构化状态 + 用确定性或概率校验器更新状态"。这与项目的分层设计完全同向，可以作为方法论依据，而不只是"课程要求用传统算法"。

**论点二（工程依据）：** 一个多模态 UI 测试的工程实践报告给出了具体数字：初始误报率约 40%，加入置信度阈值（低于 0.8 转人工复核）+ 交叉验证（模型声称的元素回查视图树）后，误报率降到 12%，元素识别准确率从 78% 升到 94%。

这条对项目价值很大：它说明"**误报抑制靠的是置信度分层 + 交叉验证，而不是换更强模型**"，正是创新点 1 和 2 的核心机制。可作为"这条路走得通"的旁证（注意：是工程博客，不是论文，引用时要说明性质）。

## 2. 创新性逐条评估

### 2.1 评估口径

三个问题：**别人做到哪了？我多做了什么？用什么指标证明？** 三问答不全，就不算贡献。

### 2.2 创新点 1：分层协同检测

| 检验项 | 结论 |
|---|---|
| 别人做到哪 | 规则+LLM 两层（CHI EA'24 UI linting）；纯 LLM 基线（SlideAudit）；纯视觉分类（UIS-Hunter） |
| 独有之处 | ① 加入**传统 ML 中间层**并给出训练与评价；② 对四类方案做**成本-效果 Pareto 对比**；③ 揭示"不同缺陷类型的**证据可得性**决定了它只能由某一层可靠检出" |
| 是否首创 | 否。分层本身不新 |
| 可否证明 | 可以。Pareto 曲线 + 方案×缺陷类别矩阵，是能画出来的硬结果 |
| 被质疑时怎么答 | 不说"我提出分层"，说"我把分层的**收益**量化了：在 X 类缺陷上，规则层以 0 LLM 调用达到与大模型相当的召回" |

**判断：可作为核心贡献，但必须把落点放在"成本量化"和"证据可得性"上，而不是"我做了三层"。**

### 2.3 创新点 2：多源证据约束

| 检验项 | 结论 |
|---|---|
| 别人做到哪 | hybrid linter 把结构属性喂给 LLM；CritiqueCrew 提到 evidence layer；但都是"辅助 LLM 判断"，不是"每条结论强制绑定可回溯 ref" |
| 独有之处 | ① 每条结论强制携带 `evidence.ref`，空证据不允许存在（已写入 schema）；② 三态状态机把"不确定"显式化；③ 检测器冲突触发复核，且复核次数计入成本 |
| 是否首创 | 机制不新，"强制举证 + 可核算"的严格程度较新 |
| 可否证明 | 可以。实验三比"直接问模型"与"证据约束"两种方式，算**无依据断言比例**、定位命中率 |
| 被质疑时怎么答 | 关键在定义"无依据"：结论中提到的页码/对象/数值，能否在 evidence 里找到对应 ref。这是可自动核验的 |

**判断：这是三个点里最扎实的一个。它输出的不是"更准"，而是"可审计"，而可审计恰好是大模型审查最难解决的痛点。**

### 2.4 创新点 3：AI 风格痕迹

| 检验项 | 结论 |
|---|---|
| 别人做到哪 | 商业产品（Turnitin、PPTDetector）做**来源鉴定**；设计博客有大量定性描述（布局重复、装饰冗余、层次单一）；但没人做**指标效度验证** |
| 独有之处 | 主动放弃"是不是 AI 做的"，改判"是否出现可观测的模板化、冗余、层次弱"，并对指标本身做一致性检验 |
| 是否首创 | 场景内没人做，但技术上（相似度、计数、比值）都是常规手段 |
| 可否证明 | **这是最大问题。** 需 60–100 页人工标注才能验证，两周内不可能 |
| 被质疑时怎么答 | 若只有 20–30 页，不能声称"检测器有效"，只能说"指标计算可行 + 初步观察" |

**判断：立意最好，但两周内只能做成"指标计算 + 小样本描述性统计"，不能做成"检测器"。必须降级，否则会拖垮整体。**

### 2.5 综合判断

| 标准 | 判断 |
|---|---|
| 本科课程期末 | **够用且偏扎实。** 有真实对照实验、有成本分析、有可追溯产出 |
| 课程评分风险 | 低。唯一风险是"三个创新点像三篇小论文拼接"，需用统一记录结构串成一条线 |
| 学术发表 | 不够。缺大规模标注、缺与 SlideAudit 基线的严格同设定对比、缺用户研究 |
| 一句话定位 | 不是"我发明了分层检测"，而是"**我在 AI 生成 PPT 的交付前审查场景里，把'哪些问题该由谁检、凭什么信、花多少钱'量化了**" |

## 3. 两周可行性

### 3.1 工作量拆解（按 9 项最低交付全做）

按学生实际投入计：工作日 4–5 小时，周末 6–8 小时，两周约 **60–80 工时**。

| # | 任务 | 工时 | 风险 |
|---|---|---|---|
| 1 | 数据获取与核查（SlideAudit 抽样、PresentBench 抽样） | 4h | 低 |
| 2 | PPTX 解析（元素几何、字体、文本、层级） | 8h | 低 |
| 3 | **渲染管线**（→PNG，中文字体，与解析同源） | 12h | **高** |
| 4 | 规则检测 4 类 | 10h | 中 |
| 5 | 特征提取（SlideAudit 图 + descriptions） | 10h | 中 |
| 6 | LR/SVM 训练与评估（含分组划分防泄漏） | 10h | 中 |
| 7 | 多模态接入（语义类缺陷 + 结构化输出） | 10h | 中 |
| 8 | 融合 + 报告生成（基于已定 Finding 结构） | 12h | 低 |
| 9 | 对照实验（5 方案 × 8 类）+ 指标计算 | 12h | **高** |
| 10 | 自建 PPTX 样本（5–10 份 + 人工核对） | 10h | **高** |
| 11 | 文档与演示材料 | 12h | 低 |
| | **合计** | **110h** | |

**缺口：约 30–50 工时。全做不完。**

### 3.2 三项必须砍

| 砍掉 | 理由 | 省下 |
|---|---|---|
| AI 味 60–100 页标注与分类器 | 标注 + 一致性检验 + 训练，两周内做不完，且做出来样本量也撑不住结论 | 15h+ |
| PresentBench 238 任务全量生成 | 需调多家 API、成本与时间都不可控；它的价值在 checklist 参照，不在跑量 | 10h+ |
| 五方案对比（A–E） | 砍到三方案（规则 / 大模型 / 分层），已足以支撑核心论点 | 6h |

**砍后合计约 75 工时，可行但无余量。**

### 3.3 关键路径

```
第1–2天  数据核查 + 样本 PPTX 体检        ← 决定后面能不能做
第3–5天  解析 + 渲染跑通                  ← 唯一硬卡点
第6–7天  规则检测 3 类 + 小样本验证
第8–9天  SlideAudit 特征 + LR/SVM（分组划分）
第10–11天 大模型语义层 + 融合
第12天   报告生成
第13–14天 对照实验 + 文档
```

**第 5 天如果渲染还出不来图，立刻降级**：放弃"渲染图特征"，ML 层改用 SlideAudit 已有的图像做独立实验，规则层与语义层在 PPTX 上跑，两层不强求同源。这样会削弱"统一证据"的叙事，但能保住交付。

### 3.4 五个真实风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **样本 PPTX 是图片式的**（一页一张大图） | 中高 | 结构证据直接归零，整个规则层失效 | 第 1 天就检查：解析后 shape 数量、是否只有一个 picture |
| 渲染字体缺失导致溢出误判 | 高 | 规则层假阳性泛滥，实验结论不可信 | 渲染前预检字体；把"字体被替换"记为独立证据 |
| SlideAudit 类别与本项目编码对不上 | 中 | ML 实验只能覆盖少数类别 | 先做标签映射表，映射不上的不训 |
| 数据泄漏导致指标虚高 | 中 | 实验一可信度归零 | 按原始页面分组划分，写进实验设置 |
| 大模型输出不稳定，结构化解析失败 | 中 | 语义层数据不齐 | 固定 schema + 重试 + 失败样本单列，不静默丢弃 |

### 3.5 两周能做出什么（承诺边界）

**能承诺：**
- 一个能打开真实 PPTX、出页面图、出元素坐标表的工具
- 3 类确定性规则检测，在自建注入缺陷样本上有明确 P/R
- 1 个在 SlideAudit 上训练并评价的 ML 检测器（1–2 类缺陷，含分组划分）
- 1–2 类大模型语义审查，输出带证据引用的结论
- 三方案对照实验（准确率 / 误报率 / 调用成本）
- 一份逐项可追溯的风险报告

**不能承诺：**
- AI 味检测器的有效性（只能给指标计算 + 小样本观察）
- 与 SlideAudit 论文基线的严格同设定对比（需复现其 prompting 设置）
- 用户审查时间下降的量化（需真人实验）
- 自动修改

## 4. 对原有表述的三处修正建议

| 原表述 | 问题 | 建议改为 |
|---|---|---|
| "构建融合确定性规则、传统机器学习和多模态大模型的分层检测框架" | 分层非首创，这样写会被问"你和 hybrid linting 有什么区别" | "量化不同缺陷类型在规则/ML/大模型三种证据路径上的**效果-成本权衡**，并给出分层调度依据" |
| "建立结构化证据体系" | 描述做法，不描述贡献 | "强制每条结论绑定可回溯证据，使**无依据断言比例**成为可测量指标" |
| "AI 风格痕迹审查" | 容易被误读为来源鉴定，且两周做不出检测器 | "AI 生成视觉同质化的**可计算指标构建与效度检验**（首批仅做指标层）" |

## 5. 需要立刻确认的三件事

1. **手上有没有 Office。** 决定渲染走 COM 还是 LibreOffice，也决定第 3–5 天会不会卡死。
2. **有没有一批真实 AI 生成的 PPTX**（Kimi / Gamma / WPS AI / 讯飞等导出）。若有，省掉 5–8 小时；若全是图片式，需改方案。
3. **两周后的交付形态**：是"报告 + 现场演示"，还是"报告 + 可运行系统 + 答辩"。这决定第 11 项（文档与演示）占多少，以及要不要保留界面。
