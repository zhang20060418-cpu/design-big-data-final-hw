# 实现流程与架构

## 一次上传的处理链路

```text
网页 / CLI / MCP
        ↓
上传校验与任务配置
        ↓
OpenXML 对象解析 + PowerPoint 原始渲染与实际排版测量
        ↓
结构规则 + 六类专用检测 + 可选 CLIP 辅助
        ↓
证据合并、跨页分析与按需多模态复核
        ↓
页面与对象定位、解释、报告、修复及前后比较
```

`backend/app/services/orchestrator.py` 组织任务。上传副本、实际测量、页面原图和结果之间保留身份与摘要，检测时复用同一次处理的对象与图像，避免使用历史实验预测代替新文件的审查。

## 对象、页面与文档证据

结构层解析文字、边界、字号和对象关系；PowerPoint 提供实际文字排版测量及原始页面图。六类专用检测进一步使用信息区域、角色、遮挡、空间占用和跨页相似关系，将页面级风险落到可查看的证据上。

检测实现在 `detector_runtime/experiments/` 保持冻结版本，应用只调用实时所需的纯函数与测量适配器，不启动研究批处理，也不读取 benchmark 标注或缓存预测。`backend/models/six_runtime_manifest.json` 用相对路径逐文件验证实现与配置的 SHA256。

## 可选的学习模型与多模态复核

CLIP 辅助分支使用 512 维图像表示和 10 维版式特征，按冻结的归一化与拼接方案得到 522 维表示，再交给项目训练的小型分类器。该分支提供四类页面风险的辅助概率和冻结工作点，默认关闭。

多模态复核围绕已有候选和实际证据进行调度，可控制检查范围与调用预算，并保留失败、中断、继续审查与复核结果。模型判断与原始规则证据分别保留，帮助用户理解建议来自哪一层。

## 报告与修复

后端合并重复候选，维护问题、对象、页面和证据引用。工作台逐页展示结果，并导出 JSON、HTML 与 PDF。规则修复处理可明确操作的对象属性；AI 修复通过受约束的方案修改文稿，再提供结果文件与前后比较。修复效果受对象结构及模型能力影响，复杂设计调整仍可能达不到预期。

## 数据与服务边界

`frontend/` 是界面，`backend/` 是任务和文件的管理者，`tooling/` 是 API 客户端。常规使用由后端同时提供前端成品与 API。上传数据、任务数据库、渲染图和密钥位于本机 `backend/data/`；检测代码及模型缓存位于 `detector_runtime/`。开启外部模型调用后，选中的页面内容会发送给配置的服务。
