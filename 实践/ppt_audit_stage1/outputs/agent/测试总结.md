## 5. 融合结论

| 对象 | 异常程度 | 证据可靠性 | 最终缺陷严重度 | 最终状态 |
| --- | --- | --- | --- | --- |
| R1 AddAgenda p3 | high（外框越界 41.6 pt） | high | none | 未发现问题（可见文字止于 370.8 pt） |
| R2 Calibri p14 | medium（外框越界 30.9 pt） | high | none | 未发现问题（可见文字止于 530.5 pt） |
| R3/R4 空形状 | low | high | none | 不适用（无可见文字，不代表整页无缺陷） |
| V1 正常对照 | none | high | none | 未发现问题 |
| V2 复杂背景裁切 | high | high | **high** | 确认问题：第二行被页底切断，第三行不可见 |
| V3 文字被覆盖 | high | high | **high** | 确认问题：红块覆盖正文中部 |
| V4 低对比文字 | low | medium | **low** | 可能有问题：可读性需人工确认 |

结论：**2 条确认问题、1 条可能有问题、0 条待人工核实、3 条未发现问题、2 条不适用**。
其中 R1/R2 说明“外框越界 ≠ 文字被裁切”；V2/V3/V4 说明规则闭环之外确实存在需要看图的可见问题。

## 6. 本次修正（验收反馈）

| 问题 | 修正前 | 修正后 |
| --- | --- | --- |
| 本地低置信 + 视觉反向 | `fuse()` 在读取模型结果前就按 `confirmed_clip` 返回“确认问题” | 先判方向冲突；本地说裁切、视觉说没问题（或反向）→ “待人工核实” + `evidence_conflict=true` |
| 空形状 | `skip` 写成“未发现问题” | 输出“不适用”，不并入未发现问题 |
| 未检查对象 | 193 个 `not_checked` 被算进“省掉的 API 调用” | 单独统计为覆盖缺口，`not_checked_counted_as_savings=false` |
| 成本口径 | 只有“避免调用”一个总数 | 候选 8 / 规则闭环 5 / 需复核 3 / 成功复核 3 页 |
| 页面覆盖 | 只有 checked / not_checked | complete / partial / not_checked 三分类 |
| 真实 API | 只写“无 Key” | 显式 `real_api_integration.status=not_completed`，并保留复跑命令 |

回归测试 `test_fuse.py` 固定了关键用例：本地 `confirmed_clip / low` + 视觉 `no_visible_problem / high`
必须得到“待人工核实”，且原因包含“证据冲突”。

## 7. 已知限制

- 第三阶段测试页是合成的，用于验证调度与复核能力，不代表真实语料的缺陷分布。
- 文字可见性只覆盖 195 个对象中的 2 个；193 个 `not_checked` 不能当作“无缺陷”。
- 遮挡规则只算 z 序 + 填充 + 轴对齐外接框，旋转对象、组合对象、半透明遮罩可能低估。
- 可读性判断带主观性；V4 的 `low_readability` 是“可能有问题”，不是确定性缺陷。
- 冲突融合路径目前由合成单元测试覆盖，现有 8 条 finding 没有真正命中“本地/视觉相反”的情况。
- 真实第三方 API 联调尚未完成：本机无 Key，3 次复核是宿主看图（`mode=host`），Token 与费用不可得。
- 未做全页扫描、未训练模型、未修改原始 PPT（6 份源文件 SHA-256 全部未变）。
