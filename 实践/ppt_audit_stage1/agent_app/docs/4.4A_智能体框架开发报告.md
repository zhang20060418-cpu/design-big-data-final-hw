## 二、技术方案

### 2.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | React 18 + TypeScript + Vite 6 | 自建设计系统（CSS 变量），无重型 UI 框架 |
| 后端 | FastAPI 0.162 + Pydantic 2 | REST API、统一错误结构、OpenAPI 文档 |
| 存储 | SQLite（标准库 sqlite3） | 任务、阶段、设置；WAL 模式 |
| PPTX | python-pptx 1.0.2 + lxml | 只读解析，递归 group shape |
| 渲染 | PowerPoint COM（pywin32） | 独立子进程，按原始比例导出 PNG |
| 报告 | Jinja2 + Pillow | 自包含 HTML（缩略图 base64）+ JSON |
| 复核 | httpx | OpenAI 兼容 `/chat/completions`，支持图片 |

### 2.2 目录分层

```text
agent_app/
├─ backend/app/
│  ├─ routers/      # HTTP 接口
│  ├─ services/     # 解析、渲染、规则、模型、复核、整合、报告
│  ├─ storage.py    # 持久化
│  └─ config.py     # 路径与限制
├─ backend/models/  # 视觉模型唯一接入点（当前空）
├─ backend/tests/   # 9 个测试
├─ frontend/src/    # 页面、组件、API 客户端
└─ fixtures/        # 系统生成的演示文稿
```

应用代码与研究代码完全分离：`agent_app/` 不 import `ml_stage4` 的任何脚本，只读取用户上传文件。

### 2.3 任务流水线（8 阶段）

```text
validate → parse → render → structure → visual → mllm → merge → report
```

状态机：`draft → preparing → ready → queued → running → completed / completed_with_errors / failed`

每个阶段记录：`pending / running / done / skipped / unsupported / failed`、消息、进度、起止时间、结构化 detail。
`unsupported`（未接入）与 `skipped`（用户关闭/未配置）都不会显示为“已完成”。

任务采用两阶段交互：

1. 上传时只执行 `validate + parse + render`，状态 `ready`，用于确认文件与预览；
2. 用户确认配置后 `POST /api/tasks/{id}/start`，复用已生成的解析与渲染产物，只执行后 5 个阶段。

这样既满足“先确认再审查”，也避免重复渲染。

## 三、实际实现的功能

### 3.1 文件上传与解析

- 拖拽 / 点击选择，支持中文文件名与空格；XHR 上传显示真实百分比。
- 安全校验：扩展名、ZIP 容器、`[Content_Types].xml`、`ppt/presentation.xml`、宏工程拒绝、解压比/总大小限制、80 MB / 200 页上限。
- 解析内容：页数、页面尺寸与比例、文本框数量、字符数、图片、表格、图表、字体、显式字号、元素坐标、组合形状递归、整页位图识别。
- 页面分类：`editable / mixed / image_only`，判定依据是整页图片覆盖率与对象层字符数，不只看“有没有文本”。

### 3.2 按原始比例渲染

- 长边固定 1920 px，另一边按真实页面比例计算，**不强制 16:9**。
- 已验证 16:9（13.333×7.5 in）、3:2（11.25×7.5 in）等比例；`slide_width/height` 直接来自 PPTX。
- 独立子进程 + 超时终止进程树，避免 COM 挂起拖垮服务。
- 渲染前后校验源文件 SHA-256；不叠加任何诊断框。
- 生成 640 px 缩略图用于导航与报告内嵌。

### 3.3 结构规则（Layer 1）

实现 R01–R05 五条可解释规则与 R06/R07 两条能力提示，详见 README。每条问题包含：

`issue_id / document_id / slide_index / defect_type / rule_id / evidence_summary / element_id / bbox / severity / confidence / review_status / recommendation`

规则只输出候选，不冒充确认缺陷；坐标以英寸记录，前端按页面尺寸换算成百分比叠加标记。

### 3.4 视觉模型接入位（Layer 2）

`backend/app/services/visual_classifier.py` 提供稳定契约：

```python
service.status()  # ready / not_configured / error + model_version + work_point
service.predict_slide(png_path, document_id, slide_index, config)
service.predict_batch(pages, config)
```

- 无 `backend/models/visual_model.json` 时状态为 `not_configured`，任务阶段为 `unsupported`；
- 有清单时动态加载 `python_module` 实现，校验四类概率、阈值与返回值；
- 模型异常按页记录，不拖垮任务；
- **没有内置任何模拟模型或假概率**。

### 3.5 多模态按需复核（Layer 3）

- OpenAI 兼容接口，Base URL / Key / 模型 / 超时 / 重试 / 并发 / 温度 / JSON 模式均可配。
- 复核策略：仅高风险页 / 全部页 / 手动选页 / 不复核；预算受任务与全局双重限制。
- 发送内容：选中页 JPEG（长边 1400）+ 该页结构候选摘要 + 四类定义与严格 JSON 输出要求。
- 结果结构化：`status / verdicts[] / overall_note / model / latency / error_code`，逐页保存。
- 失败分类：鉴权失败、网络失败、超时、限流、接口不兼容、模型不支持图片、响应格式错误。
- 失败不影响已完成阶段，任务标记 `completed_with_errors`，报告保留错误记录。
- SSRF 防护：非本机默认强制 HTTPS，可由用户在设置页显式放行明文 HTTP；解析 DNS 后阻断链路本地/云元数据地址；私网地址需单独开关放行；URL 内嵌凭据一律拒绝。

### 3.6 证据整合（Layer 4）

- 结构候选、视觉告警、AI 复核按 `(slide, defect_type)` 归并；
- 多源问题保留 `sources[]`，不合并成一个虚构置信度；
- AI 判定为 `supported / rejected / uncertain`，分别改变 `review_status`；
- AI 可提出规则未发现的问题，标记 `ai_only`；
- 报告区分“候选 / 告警 / AI 支持 / AI 不成立 / 未复核”。

### 3.7 报告

- **JSON**：完整任务、文稿、阶段、问题、复核、风险、局限、配置。
- **HTML**：自包含、响应式、打印友好；缩略图 base64 内嵌；含 DEMO 横幅（演示任务）。
- 明确列出：未接入模块、位图页限制、字体替换风险、估算偏差、AI 非真值。
- 不生成“设计质量 92 分”之类未经验证的分数。

### 3.8 任务管理

- 创建、准备、开始、查询、逐页、问题、模块状态、报告、删除。
- 浏览器刷新/重开后可凭 URL 或历史任务恢复。
- 运行中任务禁止删除；异常文件清理；同一任务重复提交有 `_running` 去重。
- 并发上限 2（可配）。

## 四、前端设计

### 4.1 视觉语言

主题为「AI Design Lab / 智能视觉审查实验室」：

- 浅色实验台画布 + 深色仪器面板，靛蓝 `#3B4CF0` 与青色 `#00B3BD` 为主色，橙色只用于风险；
- 左侧 88 px 深色导航轨，顶部品牌标识，底部竖排版本号；
- 首页扫描预览：幻灯片骨架 + 移动扫描线 + 字号/遮挡/溢出标签，表达“逐页体检”；
- 三层能力以不同图标色区分；阶段流水线用节点与连线表达，而不是一根进度条；
- 结果页采用专业设计软件式三栏：缩略图导航 / 深色画布查看器 / 证据面板；
- 报告页作为“设计诊断报告”，大标题、统计卡、分布条、高风险列表、模块矩阵、执行轨迹。

动效克制：扫描线、页面淡入、运行节点旋转；全部受 `prefers-reduced-motion` 约束。

### 4.2 可用性

- 全中文；桌面优先，适配 1366×768 与 1440×900；
- 加载态（骨架）、空状态、错误态、上传进度、阶段失败原因；
- 键盘：Tab 焦点环、Enter 打开任务、← → 翻页、+ / − 缩放、0 复位；
- 结论不只靠颜色：风险等级、来源、状态均有文字徽标；
- 未接入模块的开关禁用，并在原位置解释原因与后续接入方式。

## 七、安全与数据隔离

1. **研究数据零写入**：应用只读写 `agent_app/backend/data`；未修改 `benchmark_pptx*`、`benchmark_manifest.csv`、`review_history.json`、模型文件与 G-2 协议。
2. **上传安全**：格式/容器/宏/解压比/大小/页数校验；文件名只作展示，不参与路径。
3. **路径安全**：任务 ID 正则 `^[a-f0-9]{16}$`；图片、报告、删除均从 ID 派生路径并校验根目录。
4. **密钥安全**：仅后端读取；`GET /api/settings` 返回掩码；错误信息脱敏；报告与日志不含 Key；`.gitignore` 排除 `data/` 与 `.env`。
5. **网络边界**：设置接口仅本机；Base URL 协议/主机/DNS 校验；阻止云元数据地址；默认不放行私网。
6. **权限**：单用户本地应用，无账号系统；所有接口默认只监听 `127.0.0.1`。
