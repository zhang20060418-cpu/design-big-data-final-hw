# API 配置后默认 LLM 复检与 5 秒跳过窗口

实现日期：2026-10-31。沿用当前应用界面与冻结检测器，CLIP 仍默认关闭。

后续已补充阶段旁的提前跳过、旧待审任务默认勾选修正，以及官方 DeepSeek 输出预算兼容。当前行为及真实 API 验收见 [复核失败修复](llm_review_failure_fix.md)。下文保留首次 5 秒窗口交付记录。

## 用户流程

1. API Base URL、模型名和 Key 配置完整时，新任务默认启用 LLM；任务配置页可关闭。缺少配置时默认关闭，不自动切换 Mock。
2. R2 首轮检测及可选 CLIP 辅助复核结束后，后端先保存复检计划，再开启固定 5 秒窗口。进度页显示倒计时及「跳过 LLM 复检，查看结果」。
3. 用户在截止时间之前跳过：不调用 LLM，整理首轮结果后自动进入结果页。界面与导出的 HTML/JSON/PDF 均保留跳过状态及「可能导致误诊或漏检」提示。
4. 未跳过：后端到时自动领取一次执行授权，按既有策略和预算复检，结束后生成最终报告。加载页不提前展示首轮问题清单。复检开始后不再接受跳过。
5. 预先关闭、未配置 API、预算为零、没有可用图片或没有可执行复检范围时，不等待空倒计时。

API 配置存在不等于连通性或视觉能力已经验证。请求失败、未知范围、超预算未检查项均保持可见，不伪装成「已复检正常」。本次没有增加调用预算，也未改变模型、阈值、路由和任何人工标签。

## 一致性与故障恢复

- 每个任务的 `analysis/review_gate.json` 持久化截止时间、状态和执行授权；线程锁与跨进程文件锁保护 skip/execute 竞争。公开 API 不返回私有执行令牌。
- 浏览器倒计时仅显示后端剩余时间。刷新、轮询、双击不会延长窗口或重复启动复检。
- `POST /api/tasks/{id}/skip-review` 只在后端确认尚未截止时成功；过时操作返回 409 并刷新实际状态。
- 既有 executing/completed 记录不会自动重发请求。中断且外部结果未知时，保留失败记录，避免重复消费。
- 任务完成、报告存在且 gate 不为 waiting/executing/invalid 时才展示最终结果；直接访问结果或报告页也遵守此限制。
- 后续针对单个问题的追问单独留史，不抹去原任务曾跳过自动复检的事实。
