## 最高优先级验收

| 用例 | 触发方式 | 必须保留的事实 |
| --- | --- | --- |
| 有 API 的新任务默认开启 | 使用 `mllm.state=ready` 的 QA 配置创建新任务 | 上传时保存 `enable_mllm=true`，真实后端模式仍是 `api`，CLIP 默认关闭；默认选项不是每次轮询重复计算。 |
| 用户关闭后不恢复 | 在配置页关 LLM，等待多次 task/capabilities 返回或渲染完成 | 开关始终关闭；start 的最终 options 也是关闭，不因 ready 重新置 true。 |
| 无 API 或探测失败 | 使用 API 未配置或 capabilities 请求失败的 fixture | 不默认开启、不进入 5 秒倒计时、不自动选择 Mock；不能将未知可用性写成 ready。 |
| 旧任务保持历史配置 | 打开保存了 `enable_mllm=false` 的历史任务 | 不因今天 API 已配置就重新开 LLM，也不自动重跑旧任务。新默认仅适用于新任务的一次初始化。 |
| 首轮完成、等待复检 | 后端已完成 R2/可选 CLIP，并返回 waiting gate | 显示以服务端为准的剩余时间、跳过按钮和“跳过可能误诊/未经 LLM 复检”提示；没有“审查完成”或最终结果入口。 |
| 前端计时只显示 | 等待倒计时到 0 | 只允许轮询 GET；不能从 `setInterval`、`setTimeout`、effect 或渲染逻辑调用复检接口。到 0 后由后端独立进入 reviewing，前端显示“正在开始/正在复检”。 |
| 刷新不中断或重启窗口 | gate 等待中刷新页面，再刷新一次 | deadline 不重新加 5 秒，后端 gate ID/记录不变；不能因为 GET 或挂载组件创建第二次复检。 |
| 用户及时跳过 | 在 waiting 且 `can_skip` 为真时点击跳过 | 最多发送一次 skip POST；按钮立即忙碌/禁用；收到接受响应后仍等待后端结果融合及报告写入，不能直接展示首轮中间工件。 |
| 双击跳过 | 对跳过按钮快速双击 | 前端有防重复提交，后端原子幂等；没有两个不同的跳过或复检批次，费用不重复。 |
| 截止时间竞态 | 在 gate 过期或 reviewing 开始时发起 skip | 后端拒绝/冲突是最终事实；UI 不再宣称已跳过，不重复提交，刷新 gate 并继续显示复检进度。 |
| 复检执行后禁止跳过 | 后端 reviewing | skip 按钮禁用或移除；不能通过刷新重新得到有效按钮。 |
| 直接访问结果和报告 | waiting/reviewing 时手工输入 Results/Report URL，或浏览器后退 | 先检查服务端状态；不提前展示旧缓存或首轮 issues/report，不提供可绕过门的下载；应返回/引导进度页。 |
| 跳过后的最终工件 | 后端完成 skipped 流程及结果融合 | 页面与报告明确“用户跳过 LLM、未复检、可能误诊”，保留 R2/CLIP 原始候选，不说“LLM 支持/确认”。 |
| 正常自动复检 | 完整等待后，使用根代理提供的显式 Mock QA 任务 | 自动推进只发生一次；结束前不展示最终结果；Mock 与真实结果明确分开，真实外部调用为 0。 |
| 失败/零预算/部分预算 | 使用失败、预算为零、只复核少量候选的 QA 任务 | 不伪装成全部已确认；显示失败/未选/不确定数量和实际范围，未知不转正常。 |

## 源码审查中特别要防的竞态

- 当前 Progress 原实现仅凭 `task.status` 判断 terminal。接 gate 后，应让 `waiting/reviewing` 具有明确的“不能展示最终结果”约束；两个 GET 先后返回的瞬间也不能短暂闪出结果。
- skip 与轮询可能并行。旧的 waiting 响应不能覆盖较新的 skipped/reviewing 响应并重新激活按钮。可使用 gate 的单调版本/更新时间，或在 skip 忙碌期间冻结旧状态、接收响应后主动拉取新状态。
- 客户端时钟可能偏差。优先使用服务端返回的剩余秒数/服务端时间校正量；显示值可归零，但不能据客户端时间授予新的操作权限。
- 任一 gate GET 网络错误不应触发 skip、开启 LLM、关闭 LLM或展示最终结果。应说明暂时无法确认并继续可恢复轮询。
- taskId/mode 切换、组件卸载、React StrictMode 双 effect 不应留下旧计时器、旧 skip 结果或重复副作用。
- 同一窗口关闭后重开、多窗口同时查看，必须共享服务端 gate；每个前端实例均不能成为复检执行者。
- 旧应用的 failed 状态有“查看已产出内容”入口。新等待门不得误走该分支，把尚在 reviewing 的首轮工件当作最终结果。

## 保持已有行为

- CLIP 仍默认关闭；手动开启会保留 R2，关 R2 会同步关 CLIP。新的 LLM 默认不能把 CLIP顺便打开。
- 用户显式关闭 LLM或 API 不可用时不等待 5 秒；按现有非 LLM 流程生成报告，同时明确未经 LLM 复检。
- 返回/刷新可以重复 GET，不能导致上传、start、skip、review 的自动 POST。
- 页面原始五态、D6-A05 限制、真实 CLIP 四标签概率及阈值、Mock 标识仍须保留。
- 不要仅凭 mllm 阶段 `done` 给所有页写“已复检”。页面/报告仍应依据实际复检记录和未决范围。
