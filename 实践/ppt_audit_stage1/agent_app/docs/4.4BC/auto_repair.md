# AI 辅助修复：从"指出问题"到"给出可下载的修复副本"

日期：2026-10-31 初版；2026-11-01 增补「多轮复核 / 修改任务包 / 人工想法」；2026-11-01 再增补
「几何层：衬底归位、整页整理、无改动检测、提示词改造」。
不修改冻结检测模型、阈值、人工标签与历史研究工件。

## 1. 目标与边界

**目标**：审查报告只能告诉用户"第 6 页有 67% 的文字被压住"。修复层要回答下一个问题——**能不能直接给一份改好的副本，并且证明改好了**；改不动的页，要能把"原稿 + 标注画面 + 改法说明"打包交给外部模型或人。

**边界**（实现时写成硬约束，不靠自觉）：

1. **模型拿不到文稿**。它只收到"缺陷清单 + 每条允许的动作 + 该页对象与衬底坐标"，输出 JSON 选动作；真正的编辑由 `python-pptx` 在副本上执行。
2. **只改结构规则给出的条目**。视觉检测器的结论只有归一化区域、没有对象级坐标，不做对象级改写；但可以做**页面级整理**（见第 6 节），因为整理不依赖"这是哪一条发现"。
3. **原件与报告不动**。始终复制 `source/source.pptx` → `repairs/<rid>/fixed.pptx`。
4. **改完必须复检**。用**同一套** `structure_rules.analyze` 重新解析副本，按"页 + 类型"计数对比。
5. **一页多类缺陷必须都改**：同页既有越界又有遮挡时，不允许只处理第一条（见第 5 节）。
6. **不许"假装修好了"**：一页有缺陷却一个像素都没动，必须在结果里标出来并说明原因（见第 7 节）。
7. **不为消除告警而破坏版式**：不允许删内容、把字号压到 9pt 以下、隐藏元素，也不允许为了对齐把卡片里的文字挪出卡片（见第 6 节的三条护栏）。
8. **需要改内容的不硬改**：图标语义、文案、信息层级属于内容决策，交人工。

## 2. 链路

```
审查结果（Finding 列表）
  │ ① build_plan(round)：可见条目 → 每条一个动作（默认值由规则决定，视觉条目锁 manual）
  ▼
② refine：模型在 ALLOWED[defect] 里选动作 + 写理由；输入带画布/衬底/同页块坐标
  ▼
③ apply_plan：先统一解析目标，再分三段改：位移 → 字号 → 图层；每个被动过的文字块随即「收进衬底」
  ▼
④ verify：同一套 structure_rules 复检 → before / after / fixed / introduced
  │    ├─ 未勾选复核：走 ⑤
  │    └─ 勾选复核且仍有可自动修的条目：带残留条目回到 ①（最多 3 轮）
  ▼
⑤ 兜底整理：这一页仍是 0 改动时，做安全的整页整理（压边归位 / 拉重叠 / 对齐）
  ▼
⑥ render_pptx → annotate：渲染修复后页面 + 原始缺陷编号框
  ▼
fixed.pptx + status.json + plan.json + renders/ + annots/ + 前端四视图 + bundle.zip
```

## 3. 动作词表

| 动作 | 适用缺陷 | 实现 | 失败时 |
|---|---|---|---|
| `move_inside` | `content_overflow_cutoff`（R01 越界） | 按四边计算 dx/dy 移回画布，留 0.03in 边距；**随后收进衬底** | 宽于画布 → `manual` |
| `wrap_and_grow` | `content_overflow_cutoff`（R02 文本溢出） | 开 `word_wrap`，按估算行高撑高，超出底部则整体上移 | 已换行且高度够 → `skipped`（见第 7 节） |
| `raise_font` | `improper_font_sizing` | 显式字号 <12pt 提到 12pt，上限 14pt，并按新字号撑高 | 字号继承自母版 → `skipped` |
| `bring_front` | `occluded_content` | 只把**被压的文字**提到 spTree 末尾（保留卡片底色），多轮直到无遮挡；必要时反向把覆盖物压到底层 | 在组合内/锁定 → `manual` |
| `tidy_layout` | `cluttered_layout`（R04） | 整页整理：压边文字收进衬底、拉开互相压住的块、同列左边缘对齐（见第 6 节） | 无安全可动的块 → `skipped` + 原因 |
| `manual` | 留白、异常设计 | 不自动改，给出人工理由 | — |

`excessive_whitespace` / `generative_design_anomaly` 仍是 `manual`：补内容、重画图标都属于内容决策。留白页若整页只剩纯文字块且没有任何色板，兜底整理会做一次垂直居中（第 6 节）。

## 4. 复检口径

`verify()` 不读模型输出，只读**副本重新解析后的结构规则结果**：

- `before_structure`：修复前、可见且 `evidence_source == structure_rule` 的条目数；
- `after_structure`：副本复检后的条目数；
- `fixed = Σ max(0, before − after)`（按"页 + 类型"聚合，避免跨类型抵消）；
- `introduced = Σ max(0, after − before)`——**新增问题必须显式报出来**。

## 5. 一页多类缺陷：先定位，再三段写入

`apply_plan()` 分四步，顺序不能换：

1. **统一解析目标**：所有 op 先一起定位，同一动作不会重复落到同一个对象上（否则三条越界会挤到同一块文字，改一条、放过两条）。定位顺序是 `element_id` → 对象名 → 缺陷坐标（IoU≥0.35）→ 越界语义兜底；前两级只有在该对象矩形**仍与缺陷坐标吻合**时才采信，避免元素顺序漂移把改动送到别的文本框。
2. **位移**：`move_inside` / `wrap_and_grow`。
3. **字号**：`raise_font` 放大并撑高。
4. **图层**：本页只要有任何被触碰的条目，统一跑一次 `_clear_occlusions()`。

对应回归：`test_one_page_with_two_defect_types_gets_both_edits`（同页 7pt 正文 + 被色块压住的表头，断言字号 ≥12pt **且** 表头图层已提到色块之上）。

## 6. 几何层：收进衬底 + 整页整理

新模块 `services/layout_ops.py`，只改矩形，不改文字、字号、数量。

### 6.1 收进衬底

用户的原话是"出界的文本，调整后不仅不能出界，还要放在对应的圆角矩形衬底上"。做法：

- `find_card()` 找**衬底**：填充可见、未成组、面积明显大于这段文字、中心距离 ≤1.6in、且不超过整页 85%（铺满整页的底板不算卡片），取最"贴身"的一个；
- `seat_in_card()` 把文字矩形收进卡片内框（内边距 0.12in），**保持原有相对位置**，不重新居中——卡片里往往还叠着别的文字，居中会把它们摞到一起；
- 文字比卡片高时，卡片**向下延展**（受画布下边界与下方内容限制，最多 1.2in）；
- 三条护栏：衬底比文字窄一半以上 → 不认这张卡片；目标位置会压到别的文字 → 放弃；文字有 ≥45% 在卡片外 → 不搬（那多半是表格单元格或图例，不是压边）。

### 6.2 整页整理 `tidy_layout`

`cluttered_layout` 是**页级判定**（元素数 / 字符数 / 面积占比），没有对象坐标，所以没有"把某一条改掉"这回事。整理做三件事：

1. **压边归位**：把「≥55% 已在卡片内、但仍有一角探出卡片」的文字收进衬底；
2. **解除重叠**：两块文字在垂直方向互相压住且水平重合 ≥25% 时，把下面那块下移，留 0.10in；
3. **同列对齐**：同一列（水平重合 ≥50%）的文字左边缘吸附到主导左边缘，单次位移 ≤0.25in。

三条护栏（都是踩坑换来的）：

- **只碰页面级文字块**。背景色板、卡片、图片是"容器"，挪它们等于整页搬家；卡片**内部**的文字也不碰，否则文字会被推出卡片下沿（实测 P06 的标题就是这样被推下去的）。
- **不做"间距均分"**。把横跨整页的脚注提上来填缝，比原来的空档更难看。
- **不追求让 R04 消失**。R04 由元素数量决定，整理不会减少数量，所以这条永远报 `partial`，文案直说"密度指标仍需人工拆页或合并模块"。

### 6.3 兜底触发

页面上所有条目都只有 `manual`（视觉检测器结论）时，仍然跑一次整理：只要产生了几何改动，`page_changed=true`，并在每条 manual 的明细后追加"本页同时整理了 N 处间距/对齐"——条目本身仍是人工项，页面却不是原样交付。

## 7. 无改动检测：不允许"前后一模一样"

四个地方保证这一点：

1. **动作层面**：`wrap_and_grow` 若文本框本来就开了换行、高度也够，撑高不会产生任何像素变化 → 报 `skipped` 并写明"自动撑高不会改变版面，需要人工减少文字或改版式"，不再假报 `applied`。
2. **页面层面**：每页在改动前后各取一次**几何指纹**（对象名 + 位置 + 尺寸 + 显式字号，按 z 序），据此写 `page.changed`，汇总出 `summary.unchanged`。
3. **像素层面（唯一凭证）**：`services/visual_diff.py` 把修复后的渲染图与原渲染图逐像素比对。差异像素 ≥600 **且**占比 ≥0.02% 才算"画面变了"。只是重排了图层顺序的页判为**未改动**，页面上的 `applied` 条目自动降级为 `partial`，并在明细里写明"像素级比对显示修复前后画面一致……是规则按文本框面积判定出来的误报"。
4. **交付层面**：结果页对 `changed=false` 的页显示"画面无可见变化"角标（暖色）+ 页码标签变橙，并在顶部给出横幅，逐页列出是哪几页、原因写在动作明细里；任务日志追加一条"N 页有缺陷但画面没有产生任何可见改动"。

为什么要第三条：用户反馈"有些页修复前后图一模一样"。查下来是真的——`R05` 判遮挡看的是**文本框面积**，而文字通常只占框内一小块，于是一批"被压文字"其实从没被挡住。`bring_front` 把它们提到最上层，XML 变了、规则不再报，渲染图却字节级相同（实测 `0 像素`）。几何指纹说"改过"，像素说"没变"，必须以后者为准。

**统计口径随之改成按动作结果计数**：`summary.applied` = 状态为 `applied` 的条目数（画面真的变过），`partial` = 写了但没生效，`manual` = 留待人工，`skipped` = 无从下手；四者之和等于条目总数。规则层面的清零数单独记为 `rule_resolved`，不再冒充"已修复"。

## 8. 多轮 LLM 复核（可选，默认关闭）

发起修复时勾选「LLM 复核」，`review=true`：每轮 `build_plan(round)` → `refine(context)` → `apply_plan` → `verify`；`refine` 额外收到 `round` / `max_rounds` / `previous` / `user_hint` / `layouts`。

**停止条件**（四条，任一命中即停）：

| 条件 | 日志 |
|---|---|
| `after_structure == 0` | 结构规则已全部通过，停止后续轮次。 |
| 剩余条目**全部**是 `manual` | 剩余 N 条都属于必须人工重排的版式问题，停止自动轮次。 |
| 与上一轮相比 `after` 没有下降 | 第 N 轮没有进一步减少结构问题（仍为 X 条），停止继续消耗模型调用。 |
| 达到 `max_rounds`（默认 3） | — |

> 判断"还值不值得再跑一轮"用的是 `PROVABLE`（位移 / 换行 / 字号 / 图层）四类，整理是幂等的，不参与轮次判断。初版用 `after >= before_structure`（`before` 是原稿基线）导致条件恒真、白跑两轮，已修。

## 9. 人工修改想法

- 存储 `repairs/hints.json`（task 级共享，单页 600 字，空串即删）；
- 注入 `refine` 的 `user_hint` 与单页 prompt 的「人工附加要求（必须遵守）」；

## 10. 修改任务包：给外部 LLM 的交接材料

`GET /api/tasks/{id}/repairs/{rid}/bundle` → `{文稿名}_修改任务包.zip`，含 `source.pptx`、`fixed.pptx`、`annotated/sNNNN.png`（原图 + 编号框）、`prompt.md`、`plan.json`。

单页 prompt 现在包含：尺寸 / 页码 / 标注图名；每条缺陷的**对象、坐标、所属衬底**、现状、期望、系统已完成或未处理；人工想法；**版式要求**（衬底内不压边、同列对齐、不许靠删内容通过）。

标注图两种画法：有 `bbox` → 编号框 + 左上角徽章；无 `bbox`（整页判断）→ 左下角向上堆叠文字徽章「N 类型 · 无对象坐标，整页判断」。放左上角会挡标题，这是实测后改的。

## 11. 提示词改造

调度提示词从"选个动作"升级为"按版式规矩修"（`PLAN_SYSTEM` 9 条 + `LAYOUT_RULES`）：

1. 判断标准是**这一页像不像正常设计**，不是告警消没消失；
2. 每条缺陷都要给决定，同页多条**全部处理**，不许只挑最显眼的；
3. 文字必须落在所属圆角衬底内，不压边、不出卡片，**保持原对齐关系**，不要一律居中；衬底装不下时向下延展，但不能越出画布或压住下方内容；
4. 同列左边缘对齐、同行上边缘对齐，相邻块间距 0.10–0.30in；
5. 不许用删内容 / 压字号 / 隐藏元素来通过；
6. 只有改文案、换图、重画图标才选 `manual`；
7. `round`/`previous` 时换另一种允许动作；
8. `user_hint` 时向用户意图靠拢；
9. 语气坚定，不写"可能/也许"。

输入侧同时补了 `canvas`（画布尺寸与边距）、`pages[].cards`（每张衬底的矩形与被它承托的块）、`pages[].blocks`（同页块坐标）和 `layout_rules`——不告诉模型"这句话属于哪张卡片"，"放回衬底"就只是句空话。

| `/repair/:taskId/progress` | 五阶段进度 + 每轮复核结果 |

本轮新增：`changed=false` 页的"画面无可见变化"角标（暖色）+ 页码标签变橙、顶部「N 页有缺陷但画面上没有可见改动」横幅（附原因说明）、"整理 N 处"角标、「本页动作」头部追加"顺带整理 N 处 / 部分 N / 画面无可见变化"，以及 KPI 口径调整：第一个 KPI 变成「条已修复（画面已变）」，第二个把 `partial` 一起算进「条待人工 / 未生效」。图片标题栏右侧还会跟着一行像素比对结论（例如"画面变化 0.85%（17537 像素）"）。

## 14. 测试

`tests/test_repair.py` **29 项** + `tests/test_visual_diff.py` **5 项**，锁住九条承诺：

1. 视觉检测器条目永远是 `manual`；
2. 模型不能发明动作、不能改写锁定行，失败退回规则计划；
3. `fixed` 由同一套规则复检得出，边界/字号/换行可测量；
4. **同页多类缺陷都改**（`test_one_page_with_two_defect_types_gets_both_edits`）；
5. **移回画布后落回衬底**（`test_moved_text_lands_inside_its_card`）；
6. **只剩视觉条目时页面也要动**（`test_page_with_only_a_locked_finding_still_gets_tidied`）；
7. **改不动就如实报**（`test_wrap_and_grow_admits_when_it_changes_nothing`）；
8. **prompt 带衬底与版式规矩**（`test_prompts_carry_the_card_and_the_layout_rules`）+ 标注图 / 任务包 / 人工想法 / 多轮停止条件；
9. **画面没变就不许报已修复**（`test_layer_only_repair_is_reported_as_no_visible_change` + 像素比对的 5 项单测：同图、真改动、抗锯齿噪声、缺基准图、降级不误伤人工条目）。

后端合计 **301 项通过**（`pytest -q`，约 1.5 分钟，含 PowerPoint 渲染链路）；前端 `npm run typecheck && npm run build` 通过。

> 测试用的假渲染器 `_fake_render` 按"每页几何指纹"画 8 格黑块，几何一变画面必然不同；另有 `_blank_render` 专门模拟"改了图层但画面一致"的故障态。用纯白图当渲染结果会让所有修复都像空操作，反而掩盖要测的问题。

## 15. 已知限制

1. **组合内对象**不能自动移动（需要整体移动组合），会标 `manual`。
2. **继承字号**改不了：字号来自母版/占位符时 `raise_font` 报 `skipped`。
3. **表格单元格文字**只能移回画布：把单元格文字单独搬进卡片会吃掉表头，系统会拒绝这种归位。
4. **R04 密度指标不会因整理而消失**：它由元素数量决定，整理后仍报 `partial`，需要人工拆页。
5. **视觉条目无坐标**：对象级改写一律不做，只做页面级整理。
6. **每轮复核都是一次完整模型调用**，默认上限 3 轮。
7. **prompt 只是交接材料**：导出给外部 LLM 的改法未经本系统验证。
8. **每次最多保留 6 份修复记录**（`MAX_REPAIRS`）。
9. **修复不等于是"正确设计"**：复检只证明原规则不再触发，不证明版面变好看。
10. **R05 遮挡判定按文本框面积，会误报**：文字通常只占框内一小块，框被盖住≠字被盖住（P05/P09 实测 16/49 个"被压文字"其实一直可见）。像素复核会把这些条目降级、并在 UI 上标"画面无可见变化"，但**根治要改 R05 的判定口径**（改成按墨迹/字形范围判），会牵动与人工标签的对齐，本轮没动。
11. **像素阈值是经验值**：600 像素 + 0.02% 双门限来自本机 1920 长边的实测分布（误报 372 px、真改动 1793 px）。换渲染分辨率或加投影/透明效果时需要重测。
