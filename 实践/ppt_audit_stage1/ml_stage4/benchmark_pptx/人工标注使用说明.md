# PPT 设计缺陷人工标注工作台

这是完全离线的人工标注工具。图片与标注记录均在本机，网页不加载模型预测。不要双击 HTML 启动；需要下面的本地服务才能可靠保存 CSV。

## 1. 启动

在 Windows PowerShell 中直接复制执行：

```powershell
& 'D:\Codex_Project\Homework\Design_big_data\Final_Hw_修改\实践\ppt_audit_stage1\ml_stage4\.venv\Scripts\python.exe' -B 'D:\Codex_Project\Homework\Design_big_data\Final_Hw_修改\实践\ppt_audit_stage1\ml_stage4\benchmark_pptx\review_app.py'
```

服务默认自动打开浏览器，也可以访问 **http://127.0.0.1:8765/**。只监听本机，浏览器与服务都无需联网。保持 PowerShell 窗口打开；按 Ctrl+C 停止服务。

若端口已被占用，先确认是否已启动本工作台；确需其他端口时在命令末尾增加 `--port 8766`，按终端显示的新地址访问。标注时只启动一个服务实例。

## 2. 开始逐页核验

首次进入时填写自己实际使用的「审核者编号」。没有填写也可看图，但不能保存审核操作。原始页面、修改版本都需要逐页亲自检查；修改类型只表示生成意图，不代表标签成立。

四类中文标签分别对应原清单的字号不合理、内容遮挡、布局拥挤、内容溢出或裁切。每类选择：

- **存在缺陷（1）**：人工确认该类问题确实影响阅读或信息完整性。
- **不存在缺陷（0）**：亲自检查后确认没有该类问题。
- **不确定（unknown）**：已经检查仍无法判断，需要填写原因。

没有主动操作的标签显示「尚未检查」；主动选择 unknown 后显示「已检查但无法判断」及原因。两者都不是阴性，也不能通过冻结。允许同一页多个标签为 1。「如何判断？」内有四类判定说明。

「本页四项均无缺陷」仅作用于当前页面，弹窗确认亲自检查四类后才会写入四个 0。不会批量给原图赋阴性。

## 3. 大图与同源对照

页面按真实比例展示。点击图片或按 Z 打开放大窗口，可切到原始像素 100%，用滚轮、加减按钮缩放，拖动查看文字和边缘。

修改版本可选择「对应原图」或「原图 / 修改图并排」。按 G 打开同源组，点击缩略图快速切换原始页及修改版。关系以 manifest 的 group_id 为准；共有六个包含五张图的同源组，其余组只有原始页。

只显示对应原图时，会暂停填写修改页标签；切回修改图或并排显示后继续，避免看着原图误标修改页。顶部的「专注标注」可收起详细统计，保留进度与冻结提示，为整页图片留出更多空间。

图片加载或校验失败时会明确报错，该页不能标为已核验。请先排查文件，不把加载失败当作缺陷标签。

## 4. 快捷键

| 按键 | 操作 |
| --- | --- |
| Q / W / E / R | 依次选中四类缺陷 |
| 1 / 0 / U | 给当前选中的类别填写存在 / 不存在 / 不确定 |
| N / P | 下一页 / 上一页 |
| J | 下一张尚未完成整页审核的页面 |
| G | 打开或收起同源组对照 |
| Z | 打开或关闭大图 |
| Ctrl+S | 立即保存当前待保存的操作 |

在备注、搜索、原因输入等文本控件内，普通字母和数字按正常输入处理，不触发标注或翻页。Ctrl+S 仍可用于保存。

可开启「连续标注」，选值后自动选中下一类。自动翻到下一页是独立开关，默认关闭；只在四标签明确、保存成功后生效，不替你填写任何未操作的标签。

## 5. 自动保存、恢复和撤销

标注按钮操作会自动保存，备注也会自动保存。务必看到「已保存」。标注期间请关闭 Excel、WPS 中打开的 `benchmark_manifest.csv` 工作簿及占用文件的预览；这些程序可能阻止 Windows 原子替换文件，即使没有修改 CSV 也会导致保存失败。

文件占用时，工作台只进行有限重试，随后显示明确提示，保留当前选择并暂停其他标注和翻页。**先关闭占用 CSV 的工作簿，再在原网页点击「重新保存」；看到成功提示后继续。保存未成功前不要刷新网页，也不要点击「重新载入磁盘记录」**，以免丢弃浏览器中尚未发送的选择或备注。选项在保存受阻时变灰是保护状态，保存完成后恢复可用。

**唯一标签权威文件仍为本目录的 `benchmark_manifest.csv`。** 保留原列顺序、样本顺序、ID、来源、分组、路径和工件摘要。首次修改前自动备份到：

`review_backup/benchmark_manifest.before_review.csv`

审核动作、看过但不确定的原因、操作时间、操作者和撤销历史保存在：

`review_history.json`

该文件保存审核动作证据，不是第二份标签数据库。标注时不要删除它。保存使用临时文件与原子替换；失败或意外中断可能留下 `review_transaction.json`，其中保留已经实际发生的待保存操作。不要手动删除事务文件或用它生成新的标签。

若重启后发现操作尚未写入 CSV，工作台会保留待保存记录，显示原样本、审核者、操作时间和标签变化；由人工核对并明确点击「恢复保存这次真实操作」后才恢复。恢复保留原操作身份与时间，另行记录恢复动作，不会推断标签或覆盖不一致的外部修改。若 CSV 已写入而审核历史未写完，恢复只补全同一原操作的历史，不重复创建标签操作；在完整保存确认前仍按未完成处理。摘要、来源或字段不一致时拒绝恢复，保留文件供核对。

刷新浏览器、关闭后再打开、停止并重启服务，已落盘的标注仍保留。工作台恢复上次浏览位置；审核者编号可在顶部更改。点击「撤销最近操作」恢复最近一次标注操作前的值，撤销本身也会留下历史。

更新工作台代码时，先等待原网页显示「已保存」，再在服务终端按 Ctrl+C，重新执行第 1 节启动命令，最后刷新网页。不要在有待保存操作时直接停止服务或刷新；确有中断则按上述待保存恢复流程处理。仅刷新网页不会更新已经运行中的 Python 服务代码。

如果 Excel 或其他程序修改了 CSV，工作台会显示冲突并拒绝静默覆盖。确认外部修改后再用「重新载入磁盘记录」；外部更改不会伪装成工作台中的审核动作，必要时需要重新逐项确认。

来源计划被外部修改或移走时，也会停止写入；先核对来源证据，再停止并重新启动服务。工作台不会自动接受新的来源类别。检测到冻结工件时会进入只读保护，冻结是否真实有效仍须由既有一致性检查确认。

## 6. 检查遗漏和完成审核

首页显示磁盘记录计算的四标签完成、部分完成、未开始、不确定、渲染、字体及可冻结数量。可以按进度、文稿、同源组、修改类型筛选，或点击下一张未完成。

四标签均为明确的 0/1，只代表四标签判断完成。展开「渲染和字体核验」，主动确认：

- 渲染没有额外拉伸、裁切或错误补边；受控越界造成的实际信息裁切，与导出工具错误要区分。
- 字体没有明显问题，或者已确认替代可接受并写明原因。
- 发现渲染或字体异常时填写备注，并保留问题状态。

来源核验独立于缺陷标注。D01、D02 的 C 类来源保持原定义；D03 保留 A_candidate / 待核实。工作台只读展示来源，不能自动升级 D03。来源未解决可以继续标注，但不能通过最终冻结检查；需要按既有来源流程核实证据。

全部检查满足后，主动点击「完成本页审核」才会设置 `human_reviewed=yes`、`annotation_status=reviewed`。部分标注、浏览过页面、四标签填完均不会自动设置这两个状态；以后修改已完成页面，需要重新确认。

## 7. 冻结前检查

点击「检查是否可以冻结」会显示每个未通过 sample_id 及标签、渲染、字体、来源等遗漏，调用既有校验逻辑。这个按钮不执行冻结。

人工审核完成后，可在 PowerShell 中先切换到 ml_stage4，再刷新静态画廊与报告、检查，最后由维护者明确执行既有冻结流程：

```powershell
Set-Location 'D:\Codex_Project\Homework\Design_big_data\Final_Hw_修改\实践\ppt_audit_stage1\ml_stage4'
& '.\.venv\Scripts\python.exe' -B '.\benchmark_pptx\prepare_benchmark.py' --refresh-review
& '.\.venv\Scripts\python.exe' -B '.\benchmark_pptx\prepare_benchmark.py' --check
# 仅当人工核验及来源等全部门槛通过，明确决定冻结后再执行：
& '.\.venv\Scripts\python.exe' -B '.\benchmark_pptx\prepare_benchmark.py' --freeze
```

unknown 不能自动转成 0。正式冻结前始终不得开展新基准的模型性能测试；冻结后不得根据模型预测改标签或筛页。本工具不提供预测、训练或自动冻结功能。

- 108 张真实 PNG 均成功加载；6 个五图组均按清单对应。
- 浏览器 15 组验收通过：中文按钮与 Q/W/E/R + 1/0/U、多标签、unknown 原因、输入框快捷键隔离、Ctrl+S、N/P/J、并排与同源组、大图缩放拖动、保存失败阻导航和重试、字体/渲染主动确认、当前页四项 0 的取消与确认、审核完成及撤销、图片缺失禁标、24 页可控样本筛选、刷新与服务重启、外部 CSV 冲突的显式重载。
- 后台验证通过：首次修改备份、临时文件原子替换、审核历史与事务恢复、版本冲突、来源计划改动守卫、单服务写锁、Host/Origin/路径限制。
- 临时副本中的旧 `--check` / `--refresh-review` 保留标签；旧 `--freeze` 正确拒绝未满足门槛的数据，未生成冻结文件。
- 初次验收时，正式基准原有 140 个文件 SHA-256 及旧准备报告均未改变；当时正式清单为 108 页未审核、432 个 unknown，无测试审核者与时间，frozen=false、ready_for_final_test=false。**这是初次验收的历史快照；后续真实人工标注进度必须保留，不能为复验重置成 unknown 或清空审核记录。**

保存占用问题的补充回归仍仅使用临时副本：本轮实际通过 17 项 Edge 浏览器检查和 9 项后台锁定与事务恢复检查，覆盖以下情况：

- 使用真实 Windows 文件占用锁验证保存受阻、有限重试、原 CSV 完整保留，以及解锁后重试恢复。
- 失败操作在浏览器或服务重启后仍保留；明确恢复原动作时保留原审核者和时间，不把恢复人冒充原审核者。
- CSV 已写入、审核历史未完成时的同一事务恢复，防止重复标签操作。
- 待保存操作与外部 CSV 或来源记录不一致时拒绝覆盖；普通保存成功后选项恢复可用。

本轮核对原有 139 个非标注清单文件的 SHA-256 均未变化，正式 CSV 没有混入测试身份；真实人工标注未重置。后台占用与恢复检查记录保存在 `ml_stage4/.cache/review_save_fix/`。

复验脚本为 `smoke_test_review.mjs`，使用机器已有的 Node 与 Edge，不影响日常工作台的 Python 启动。临时数据及测试结果保存在 `ml_stage4/.cache/benchmark_review_app/`，与正式基准分离。普通人工标注只需执行第 1 节的启动命令，无需运行测试脚本。
